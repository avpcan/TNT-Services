# Development guidelines

- Each commit has one specific purpose and adds or changes at most one authored function or React component.
- Commit a new component separately from changes to a function that renders it.
- Keep configuration, content, and styling commits narrowly scoped.
- Keep every commit buildable once the initial scaffold is complete.
- Use bracketed placeholders for unknown business information. Never invent contact details, reviews, credentials, or completed projects.
- Preserve the friendly, easy-going tone. The about section is called "Meet the team".
- Before delivery, run lint, typecheck, and build when Node.js and dependencies are available. Report checks that could not run.
